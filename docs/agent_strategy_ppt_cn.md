# News2ETF Agent 策略构建说明

## 1. 项目目标

本项目希望把“新闻理解 + 量化信号 + 历史经验 + 风险约束”整合到一个统一的 ETF 轮动 Agent 中，用周频的方式完成以下任务：

1. 从市场新闻和历史价格中提炼可交易的板块级信息。
2. 先判断应该配置哪些元板块，再进一步选择具体 ETF。
3. 在输出组合前加入风险约束，避免过度集中、镜像持仓和高波动追涨。
4. 通过回测和行为日志形成闭环，让策略具备可解释性和可复盘性。

一句话概括：这是一个“研究员 + 交易员 + 风控”三段式的多模块 ETF 决策系统。

---

## 2. 总体架构

整体架构可以分为五层：

1. **数据层**
   - 新闻原始数据
   - ETF 历史价格
   - ETF 基础信息与行业映射
   - 历史回测记录
   - 历史决策日志与 Memos 记忆

2. **特征层**
   - TCN/LightGBM 等模型输出的板块信号
   - 新闻摘要与情绪
   - 市场状态特征
   - 当前持仓与最近绩效
   - 情绪与价格背离特征

3. **Agent 层**
   - Researcher：负责主动调用工具，收集信息
   - Trader：负责生成最终仓位方案

4. **风险层**
   - 单板块权重限制
   - 组合总仓位限制
   - 禁闭区限制
   - 高 beta 惩罚
   - 镜像板块冲突约束
   - 最小交易阈值

5. **回测与闭环层**
   - 周频回测
   - 每周结果 parquet 持久化
   - checkpoint 恢复
   - 异常诊断工具

## 3. Agent 的核心设计思想

### 3.1 不是单次问答，而是多轮研究决策

系统不是让大模型一次性输出答案，而是采用 LangGraph ReAct 工作流：

- `agent -> tools -> agent`：研究员多轮收集信息
- `finalize`：交易员统一生成方案
- `risk_check`：风控校正方案
- 必要时重试

这种设计的好处是：

- 让模型先“研究”，再“拍板”
- 工具调用过程可追踪
- 风险控制独立于大模型主观判断
- 更适合投资场景中的多源信息融合

### 3.2 先做板块配置，再做 ETF 选择

策略输出分成两层：

1. **Level 1：元板块配置**
   - 例如：科技成长、高端制造、医药健康
   - 决定是否买入、持有、卖出，以及配置多少权重

2. **Level 2：ETF 选择**
   - 在每个元板块内选择跟踪指数和具体 ETF
   - 形成真正可交易的标的

这比直接在所有 ETF 上做选择更稳定，因为：

- 上层先做宏观行业判断
- 下层再做交易执行映射
- 结构更清晰，也更便于解释

## 4. 输入特征体系

Agent 的决策上下文不是单一因子，而是一组组合特征，主要分为 A/B/C/D/E 五类。

### 4.1 Feature A：时序模型信号

来源：`TCN sequence + ML signal snapshot`

作用：

- 描述各元板块最近数日的动量序列
- 提供 TCN 回归值、LightGBM 分数、新闻热度、情绪值、预测稳定性等

价值：

- 给 Agent 一个“模型先验”
- 避免只依赖大模型主观阅读新闻

### 4.2 Feature B：新闻摘要

来源：周内新闻 + FinBERT/SetFit ONNX 推理结果

系统会对新闻进行：

- 一级行业分类
- 二级子行业分类
- 情绪判断
- 置信度估计

然后压缩成可供大模型消费的板块新闻摘要。

价值：

- 把文本新闻转成结构化市场线索
- 让 Agent 理解“为什么这个板块最近强/弱”

### 4.3 Feature C：市场状态

来源：ETF 价格聚合得到的市场代理指标

包括：

- 1 周收益
- 2 周收益
- 波动率
- 成交量比率
- 牛市/熊市/中性状态分类

价值：

- 提供宏观环境判断
- 帮助 Agent 决定应该进攻还是防守

### 4.4 Feature D：持仓状态

包括：

- 当前持仓结构
- 已投资仓位比例
- 前 5 大持仓
- 组合最近 1 周收益
- Agent 最近 1 周/4 周绩效

价值：

- 防止决策与已有持仓脱节
- 把“行为金融”信息纳入下一周决策

### 4.5 Feature E：情绪-价格背离

逻辑：

- 如果新闻情绪在改善，但价格没有同步上涨，可能是潜在机会
- 如果价格走强但情绪走弱，可能是风险信号

价值：

- 给 Agent 补充一个“预期差”视角
- 降低只追随价格或只追随新闻的片面性

## 5. 工具系统设计

Researcher 通过工具完成主动研究，主要工具包括：

### 5.1 市场研究工具

- `read_market_news`
  - 读取一周新闻，并附带行业、情绪、置信度信息

- `compute_ml_signals`
  - 返回各元板块的机器学习信号快照

- `get_industry_top_news`
  - 查看某个行业最关键的新闻

- `get_etf_candidates`
  - 获取行业对应的 ETF 候选

### 5.2 组合记忆工具

- `check_last_week_pnl`
  - 查看上一周组合收益、净值与持仓

- `retrieve_history`
  - 从 Memos 中检索相似历史案例

- `build_decision_context`
  - 一次性构建完整决策上下文
  - 将 A/B/C/D/E 特征、好坏模式、历史案例统一打包给 Trader

- `store_decision`
  - 将决策写入历史记忆系统，形成可复盘的行为日志

工具层的作用可以理解为：把原始数据加工成“大模型可消费的研究资料”。

---

## 6. Researcher 与 Trader 的分工

### 6.1 Researcher：做信息搜集与归纳

Researcher 主要职责：

- 读取新闻、信号、历史收益与持仓
- 主动追问某些板块或 ETF 的细节
- 建立市场环境与候选板块的认知

它相当于一个“买方研究员”。

### 6.2 Trader：做最终仓位拍板

Trader 只做一件事：

- 基于研究结果输出标准化 JSON 决策

输出内容包括：

- `level1_plan`
  - 元板块、动作、权重、原因

- `level2_plan`
  - 元板块、候选指数、最终 ETF

这种分工让模型职责清晰：

- Researcher 负责“看懂市场”
- Trader 负责“做组合决策”

## 7. 风险控制机制

风控不是附加项，而是策略主链路的一部分。

### 7.1 Level 1 风险规则

对元板块配置进行约束：

- **禁闭区约束**
  - 某板块处于禁闭状态时，不允许新增买入

- **最小仓位阈值**
  - 小于 5% 的买入意图视为噪声，降级为 hold

- **单板块权重上限**
  - 单板块最大权重默认不超过 30%

- **总仓位上限**
  - 多个买入信号的总仓位超过上限时按比例缩放

- **高 beta 惩罚**
  - 如果上一周亏损，不允许新开 very_high beta 板块

- **镜像冲突约束**
  - 同一镜像/高度相关簇中，避免多个高权重板块同时重仓

### 7.2 Level 2 风险规则

对 ETF 选择进行约束：

- 去重
- 仅保留 Level 1 允许的元板块
- 如果上层板块被风险规则移除，下层 ETF 自动失效

### 7.3 执行前硬约束

在回测执行层还有更严格的约束：

- 每个买入或持有板块必须有 `selected_etf`
- 当前持仓若缺 ETF 价格数据，立即报错停止
- 单周收益超过阈值直接触发 guardrail
- 板块收益贡献之和必须与组合周收益一致
- NAV 变化必须与周收益一致

这部分保证了回测结果在会计口径上是自洽的。

## 8. 回测与执行闭环

### 8.1 回测顺序

当前回测采用周频流程：

1. 读取上一周收益、持仓和表现
2. Agent 在周初做本周决策
3. 应用仓位调整，扣除手续费与滑点
4. 计算本周实现收益
5. 更新净值与持仓漂移
6. 将本周结果写入 parquet 与 checkpoint

### 8.2 为什么需要持仓漂移

如果一周内科技涨得多、医药跌得多，那么周末时：

- 科技的仓位占比会自然抬升
- 医药的仓位占比会自然下降

系统现在会在每周结束后按实际收益率重新标记持仓权重，而不是永远停留在“目标权重”。这使得回测更接近真实资金账户的演化过程。

### 8.3 持久化与恢复

当前系统支持：

- 每周回测结果实时写入 parquet
- 指标实时写入 metrics parquet
- 每周生成 checkpoint
- 支持按指定周恢复
- 支持从最新 checkpoint 恢复

这使得长时间回测和异常中断恢复更方便。

## 9. 历史经验与自我进化机制

系统不仅看当周数据，还会提取历史经验：

### 9.1 PromptManager

通过历史决策日志提取：

- 好模式（good patterns）
- 坏模式（bad patterns）

例如：

- 在某种市场状态下，哪些板块配置历史上更容易赚钱
- 哪些动作组合在过去更容易亏损

### 9.2 Memos 检索

通过向量检索找出与当前市场最相似的历史案例，为 Trader 提供可参考的先例。

这让系统具备一定程度的“经验迁移能力”：

- 不只是看当前信号
- 还会参考历史上“类似情形怎么处理”

---

## 10. 策略优势

从策略构建角度看，这个 Agent 有五个突出特点：

1. **多源融合**
   - 同时使用新闻、价格、模型信号、历史收益与记忆系统

2. **分层决策**
   - 先做板块配置，再做 ETF 选择

3. **可解释**
   - 每个仓位都带有原因、新闻、信号和历史上下文

4. **风险内生**
   - 风控不是后处理，而是策略主链路的一部分

5. **可回测、可恢复、可诊断**
   - 具备工程级的实验闭环

---

## 11. 当前系统的边界

为了做 PPT 时表述更客观，可以明确说明当前边界：

1. 仍然是周频策略，不是日内/高频系统
2. 大模型负责策略理解与组合表达，不直接替代价格模型
3. 结果质量依赖于：
   - 新闻分类质量
   - ETF 映射质量
   - 历史价格数据完整性
   - 历史日志与记忆库质量
4. 目前更适合作为“研究辅助 + 策略原型平台”，而不是直接上线实盘

## 12. 适合 PPT 的一页总结

可以直接放在 PPT 首页或结尾页：

> News2ETF Agent 是一个基于 LangGraph 的周频 ETF 轮动决策系统。  
> 它将新闻理解、量化信号、历史记忆和风险控制整合为统一工作流，采用“研究员 Researcher + 交易员 Trader + 风控 Guardrail”的三段式结构，先完成元板块配置，再落实到具体 ETF 选择，并通过回测、checkpoint 与诊断工具形成可解释、可复盘、可迭代的策略闭环。
